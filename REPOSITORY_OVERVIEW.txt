# Project Repository Overview (Smart Fish Feeder / SmartAqua)

This repository contains a full-stack IoT aquaculture platform for **automated fish feeding, pond monitoring, and remote device control**.

It is organized as a multi-component system:
- **Backend (Go)** for APIs, business logic, telemetry ingestion, scheduling, and analytics
- **Firmware (ESP32 / PlatformIO)** for on-device control, sensing, connectivity, and motor actuation
- **Mobile app (Flutter)** for user operations, monitoring, and device management
- **Documentation scripts and proposal assets** under `docs/`

---

## 1) What the system does

At a high level, the project enables fish farmers to:
- Register and manage feeding devices
- Configure automatic feeding schedules
- Trigger manual feeding remotely
- Monitor sensor values (temperature, feed level, power/battery, connectivity)
- Receive alerts
- Track feeding events/history
- Use feed recommendations driven by biological/algorithmic logic

The platform is designed for real-world field use with intermittent connectivity and low-bandwidth conditions.

---

## 2) End-to-end architecture

Main interaction chain:

1. **Mobile app** calls backend REST APIs and reads near-real-time data
2. **Backend** manages users, devices, schedules, analytics, and command orchestration
3. **Firmware devices** (ESP32-based controllers/cameras) execute feed actions and publish telemetry/events
4. **MQTT broker** is the device messaging channel between backend and hardware
5. **PostgreSQL** persists system records and historical data
6. **Redis** supports caching/session-related operational workloads

Core communication modes:
- **HTTP/REST**: App ↔ Backend
- **MQTT**: Backend ↔ Device
- **BLE**: Mobile provisioning flow support in app stack

## 5) Firmware details

### Hardware focus
- Main board: **LILYGO T-A7670 R2** (ESP32 + A7670G LTE)
- Camera: **ESP32-CAM**
- Motor chain: NEMA stepper + DM542/TB6600 driver + auger feed mechanism
- Sensors: load cell (HX711), ultrasonic feed level sensor, DS18B20 temperature
- Power model includes solar-assisted scenarios and battery management

### Build environments (`firmware/platformio.ini`)
- `t-a7670-dm542` (default)
- `t-a7670-tb6600`
- `t-a7670-debug`
- `t-a7670-release`
- `esp32cam`
- `t-a7670-wokwi` (simulator profile)

### Config-heavy implementation
`firmware/include/config.h` centralizes:
- Pin definitions
- Motor/auger parameters
- Sensor thresholds and calibration constants
- Battery/solar thresholds
- MQTT/network settings
- Biological algorithm constants (Q10, OBM, feed-rate references)
- NVS storage key definitions

## 7) Algorithms and intelligence scope

The backend algorithm module includes grouped implementations for:
- **Biological models** (Q10 metabolism, OBM safety, growth/FCR concerns)
- **Computer vision primitives** (optical flow, blob detection, surface activity/boil index)
- **Fuzzy logic controls**
- **Reinforcement learning utilities** (DDPG, Q-learning-related components)
- **Sensor fusion** (Kalman and confidence/quality logic)
- **Signal processing and math utilities**

This indicates the system is intended to support adaptive/optimized feeding behavior beyond fixed timer-only automation.

## 10) Practical interpretation of this repository

This is a **production-oriented IoT aquaculture platform repository** that combines:
- embedded control firmware,
- cloud/API backend services,
- and a cross-platform mobile client,

with explicit support for remote management, telemetry, adaptive feeding logic, and field deployment conditions (cellular links, power variability, and intermittent connectivity).

In short: this repository is not a single app; it is a **complete multi-layer smart fish feeding ecosystem**.
